# 鲜叶收青移动业务（Flutter + Dart + Isar）

从鲜叶采摘到收青的现场移动系统：茶园区块、采法、采摘时间（可为区间）、
运输容器、芽叶组成、红变损伤逐项保留；**称重后的大批平均不覆盖任何局部事实**。
收青员在收青点用大按钮操作，全程断网可用，联网后顺序同步。

> 边界原则：系统只登记事实、核对事实、提示人工处置；
> **不自动决定等级、不自动决定价格**，领域模型里没有等级/价格字段。

## 关键事实模型

- **LeafLot 鲜叶票**：区块 blockId、采法、采摘时间区间（只有区间也合法）、
  采摘组、自述芽叶组成。一个运输批可含多张票（多茶园混装）。
- **Basket 竹篓**：二维码 `TEA-BASKET/<版本>/<站点>/<篓号>#<CRC8>`，
  记录容器类型（竹篓透气 / 编织袋塑料袋不透气）与皮重。
- **Weighing 称量**：一次过秤一条记录；**同一竹篓可分多次称量，净重逐条相加**，
  绝不用大批平均反推单篓。短时间内同篓同重量且未声明"分称"会提示疑似重复过秤。
- **Sample 小样**：按随机计划抽取，每份独立登记芽叶级配、表面水、异味、
  红变、机械伤、局部闷热标记；篓底/中层必须覆盖（闷热最易被均值掩盖）。
- **LotPhoto 照片**：摊样/标签/损伤照片先存本地路径，同步时上传回填。
- **标签雨损**：不重用旧码——拍照留证、人工核对身份、补打新签重贴；
  旧码上的历史称量不回写，保留可追溯。
- **ManualAck 人工处置**：每条 block 级提示必须有人、时间、处置意见，
  才能完成收青；info/warning 供知情参考。

## 核对规则（ReceivingService.check）

| 规则 | 级别 | 说明 |
|---|---|---|
| 采后时长 | block/warning | 超过限值且区间两端都超时→需人工处置；区间跨线→警告 |
| 采摘区间过宽 | warning | 只有宽区间、时长无法确认 |
| 抽样覆盖 | block | 小样数、篓底/中层（先摊后为摊放匾）、混装每张票必抽到 |
| 净重缺失/为零 | block | |
| 疑似重复过秤 | block | 同篓 10 分钟内同毛重且未勾分称 |
| 净重与自报不符 | warning | 逐篓净重相加后与联单自报超 5% |
| 局部闷热/红变 | block | 逐小样保留，明确"不并入大批平均" |
| 异味 | block | 逐小样（烟/药/发酵/霉/油） |
| 标签雨损 | block→info | 重贴后降级留痕 |
| 不透气容器 | warning | 提示重点查该篓小样 |
| 多茶园混装 | info | 提示按票分别保留 |
| 先摊后登记 | info/warning | 合法；采后时长以**到场时刻**为准，长期未补登记才警告 |
| 级配差异大 | warning | 各小样同名组分相差≥25 个百分点，提示勿用平均代替 |

## 五个现场场景（均有自动化测试）

1. **多个茶园混装**：两张鲜叶票各自事实保留；每张票必须抽到小样，
   漏抽时 block 且不能收青。
2. **一篓分两次称量**：9.6/7.5kg 两次过秤净重 16.3kg 相加；
   未声明分称的短时同重量重复过秤被拦截，需人工确认。
3. **采摘时间只有区间**：5–8 点采摘、14 点到场 → 采后 6~9h，
   跨超时线只警告不替人决定；两端都超时才 block。
4. **标签受雨损坏**：CRC 校验失败转人工录入；损坏未处置 block，
   拍照+重贴新签后降为 info，旧码称量保留。
5. **先摊开再登记**：到场 12:00、摊放 12:02、补登记 12:40，
   抽样计划改在摊放匾，采后时长仍按到场计算；篓底小样局部闷热红变
   独立 block，不被其他 4 份正常小样平均掉。

另含护栏测试：聚合 JSON 白名单中不允许出现 `price/level/amount/单价` 等字段。

## 运行与测试

```bash
# 业务内核（纯 Dart）
cd core && dart pub get && dart test

# 移动应用
cd app && flutter pub get
dart run build_runner build --delete-conflicting-outputs   # 生成 Isar 代码
flutter analyze
flutter test
flutter run                                                # 真机
```

需要设备权限：相机（拍照、扫码）、存储（落照片）。
离线写操作全部进入 Isar 的 `SyncQueueRecord`，联网后在"离线队列"页按顺序推送；
服务器端点实现 `ReceivingApi`（默认 `NullReceivingApi`，现场无内网时永不丢数据）。
